# RM pages — deploy steps (branch `feat/rm-pages`, built on `feat/photos`)

Deploying this branch also ships everything on `feat/photos` (Remembrance photos, book sample pages, books page).

1. **Supabase → SQL editor:** run `db/2026-11-27-rms.sql` (safe to run twice). Do this first:
   the share form's new tick box writes `items.scope`, which doesn't exist until this runs.
2. **Vercel:** promote the `feat/rm-pages` preview (asset version 18).
3. **Optional — admin waitlist shows RM requests:** redeploy the `api` edge function from
   `supabase/functions/api`. Skip it and RM book requests are still saved; see them in the `rm_book_interest` table.
4. **Data:** the assistant loads `rms`, `rm_town_links`, `rm_places` (see `rm-data/README.md`).
   Until then nothing new shows except an empty `/rm` page (not indexed by Google).

What's new
- `/rm` (all RMs by province) and `/rm/<slug>`: about the RM (sourced), its towns, hamlets / ghost towns /
  country schools / churches / post offices, cemeteries, history of the whole district, decade-by-decade
  timeline from its towns, and "Request the RM book".
- Town pages: "Part of the RM of …" under the town name (once linked).
- Province pages: "Rural municipalities in <province>" list (once loaded).
- Share form, Step 1: tick box "This is about the whole RM or district" → the item also shows on the RM page.
- Sitemap includes `/rm` pages once there are RMs.

# AI reader + book update drafts (branch `feat/ai-reader`, built on `feat/rm-pages`)

Promote `feat/ai-reader` instead of `feat/rm-pages`: it includes the RM pages.

1. **OpenRouter:** make an account at openrouter.ai, add $10 credit, create an API key.
2. **Supabase → Edge Functions → Secrets:** add `OPENROUTER_API_KEY` = that key.
   Optional: `AI_MONTHLY_CAP_USD` (default 15: the AI stops for the month once it has spent that),
   `AI_READ_MODEL` / `AI_TEXT_MODEL` (default `anthropic/claude-haiku-5.5` for both).
3. **Supabase → SQL editor:** run `db/2026-11-27-ai-reader.sql` (after the RM one). It queues the photos, clippings
   and gravestone photos already on the site, and schedules the reader (every 2 min) and book drafts (04:15 daily).
4. **Deploy the new edge function** with JWT checks off (the timer calls it without a token):
   `supabase functions deploy ai-reader --no-verify-jwt`
5. **Vercel:** promote the `feat/ai-reader` preview.

What it does
- Shared photos (visitor uploads): describes the photo and copies any writing on it (French or other writing gets an English translation; nothing is translated into French),
  at the bottom of the upload's text while it waits for your review.
- Newspaper clippings: fills in the transcription, headline, paper and date when empty (shown with the AI label),
  plus an English translation when the clipping isn't in English.
- Gravestone photos: puts the inscription into the caption while the photo waits for review. Portraits are skipped.
- Whole-book uploads: reads every page, privately. #admin → AI reader → What the AI read → Book pages → "Download all the pages' text".
- Book drafts: each morning, for each finished book, drafts the new paragraphs from history added since its last
  revision, following `book-source/BOOK-RULES.md`. #admin → AI reader → Book update drafts → edit → Approve (revision +1) or Reject.
  The approved text still has to go into the rebuilt PDF (hand it to Claude with the book source).
- Can't read yet: HEIC (iPhone) and PDF files are marked "can't read".
- Cost: about $0.50 per 1,000 pictures at Haiku prices; a book draft is a few cents.
